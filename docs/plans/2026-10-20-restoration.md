# InterestShield restoration

Approved direction: recover the calm, asset-centered Car / House / Vault experience,
retain truthful financial feedback, and improve quality without another conceptual redesign.

## Release slices

1. Financial conservation: reserve minimum payments, release payments after payoff,
   retain surplus deposits as cash, and make dashboard interest match its active target.
2. Hero collection: ten individually generated product references; reconstruct actual
   textured meshes where generation is available. Never describe a rotated flat image as 3D.
3. Presentation: recognizable assets on an unframed stage, four vitals, clear target
   balance and next move. One smooth revolution then rest; replay and reduced-motion controls.
4. HyperFrames: deterministic seekable turntables using the same local models; no
   runtime network, no CSS rotation of posters, no free-running render clock.
5. Verification: regression suite, type/build checks, desktop/mobile browser evidence,
   model framing and moving-pixel checks, asset budgets and graceful fallbacks.

## Boundaries

- Preserve the four existing dirty files and their aligned demo defaults.
- Do not replace the backend during visual restoration or add banking connections.
- Generated reference art is not a verified 3D model until its GLB is inspected.
- Do not declare production readiness from task counts. Backend isolation, lender
  terms, equal-liability comparisons, scenario ownership and deployment checks remain gates.
- A full subcategory collection is separate from the ten base-domain heroes.
